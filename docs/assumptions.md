# Labelled Assumptions & Domain Rules

In accordance with the project rules, all domain parameters not explicitly fixed in the client brief are documented below and enforced consistently across the backend engines, unit tests, and UI.

| # | Area | Labelled Assumption | Rationale & Where Used |
|---|---|---|---|
| **A1** | **Reference Clock** | `REFERENCE_DATE = 2026-11-02` | Aligns the prompt's sample dates (`2026-10-10` = **23 days overdue** for `STU-0587`; `2026-11-15` = **Due in 13 days** for `STU-0219`) to the exact day. |
| **A2** | **Academic Session Length** | **300 calendar days** (`2026-04-01` to `2027-01-25`) | Standard JEE/NEET annual coaching calendar prior to board/entrance exams; forms the denominator of the daily pro-rata refund formula. |
| **A3** | **Institute Registration Component** | **₹1,500** non-refundable administrative registration fee included within the annual fee | Labelled as an institute policy assumption (not a statutory fee). Deducted from `net_annual_fee` before computing the daily pro-rata instructional rate (`(120000 - 1500) / 300 = ₹395/day`). Study materials are digital or factored into the daily instructional rate. |
| **A4** | **MoE 2024 10-Day Refund SLA** | **10 calendar days** starting from `request_date` (not back-dated `exit_date`) | Prevents a student whose last attended class was weeks ago from triggering an already-expired statutory SLA at the moment they submit a withdrawal request. |
| **A5** | **Refund Shortfall & Withdrawal Side-Effects** | If `total_paid_to_date < pro_rata_fee_utilized`, `refundable_amount = ₹0` and the gap is logged as `shortfall_receivable` | Prevents negative refunds. Approving a refund atomically marks the student `WITHDRAWN`, cancels scheduled reminders, closes open AI tasks, blocks duplicate refunds, and issues a GST credit note reference. |
| **A6** | **GST Inclusive Calculation** | Fees include **18% GST** (`9% CGST + 9% SGST` for intra-state Rajasthan billing) | Computed as `base = round(total / 1.18, 2)`, `cgst = round(base * 0.09, 2)`, and `sgst = round(total - base - cgst, 2)` so the three components always sum to the exact rupee amount paid. If out-of-state billing occurs, 18% IGST is applied. |
| **A7** | **Automated Reminder Cadence** | 3 triggers per instalment: **`BEFORE_7_DAYS`** ($T-7$), **`ON_DUE_DATE`** ($T=0$), and **`AFTER_7_DAYS`** ($T+7$) | At dispatch time, the engine re-verifies `instalment.status != "PAID"` and interpolates the live unpaid balance (`amount_due - amount_paid`). Full payment immediately transitions queued reminders to `STOPPED_ON_PAYMENT`. |
| **A8** | **AI Risk Factor Weights & Rounding** | **Fee Friction (40 pts max)** + **Attendance Decay below 85% (35 pts max)** + **Negative Test Trend (25 pts max)**, rounded **once** at the end | Chosen as a transparent engineering judgment call so every point is explainable and unit-testable (`round(fee_pts + att_pts + test_pts)`). For `STU-0587` (Ishita): `27.467 + 26.6 + 19.8 = 73.867` -> **`74 / 100`**. |
| **A9** | **AI Unsure State & Sparse Data** | `confidence = "LOW_SPARSE_DATA"` when a student has fewer than 3 recorded mock tests | Borderline scores (`45–59`) or sparse-data students scoring `>= 45` are marked `UNSURE_BORDERLINE`, prompting manual attendance verification rather than a high-risk alarm. Students scoring `< 45` remain `LOW`. |
| **A10** | **False-Flag Resurfacing** | Dismissing an AI flag records `dismissed_at_score` and suppresses the alert unless the student's score later jumps by **`>= 15 points`** | Prevents a one-time medical leave dismissal from permanently hiding a student whose attendance or fee default worsens months later. |
| **A11** | **RBAC Roles & Demo Mode** | 3 roles: `PARENT`, `ACCOUNTS`, and `COUNSELLOR` | Parents are restricted via object-level checks (`student.id == user.student_id`). Both `COUNSELLOR` and `ACCOUNTS` can dismiss AI false flags; only `ACCOUNTS` can process refunds or match bank transfers. The 1-click reviewer switcher is gated by `DEMO_MODE=true` and mints real signed JWTs. |
| **A12** | **Over-60-Day KPI & Tally Format** | `Over-60-Day % = (Unpaid balance on instalments > 60 days overdue) / (Total matured instalment value to date)`. Tally export uses **Tally XML Vouchers** | Provides an unambiguous denominator for tracking the client's 12% to 6% target and exports receipt vouchers in Tally's native XML import schema. |
| **A13** | **DPDP Act 2023 Parental Consent** | Parent profile logs statutory consent on first OTP login (`timestamp`, `parent_mobile`, `ip_address`, `otp_session_id`). Minor students cannot transact without linked verified parent consent. | Compliance with Digital Personal Data Protection Act 2023 and Ministry of Education guidelines for minor student academic/financial records. |
| **A14** | **Unmatched Payments Queue** | Webhooks, NEFT, or UPI transactions missing a valid `student_id` or `instalment_id` are routed to `STATUS = UNMATCHED_QUEUE`. Accounts staff manual match atomically updates ledger and cancels reminders. | Guarantees audit reconciliation without false auto-credits; reduces month-end reconciliation time from 4 days to 1. |
| **A15** | **Multi-Centre & Batch Hierarchy** | Company A operates 4 centres in Jaipur (*Malviya Nagar, Gopalpura, Vaishali Nagar, Raja Park*). Ageing, dues, and Tally exports aggregate: **Institute $\rightarrow$ Centre $\rightarrow$ Batch**. | Satisfies client requirement for one consolidated view across all 4 centres by batch. |
| **A16** | **Discounts & Scholarship Proration** | Discounts (merit/early-bird scholarships) apply proportionally across instalments. Refund pro-rata daily instructional rate uses net fee after discount: `(net_annual_fee - 1500) / 300`. | Enforces mathematical integrity between discounts and pro-rata statutory refunds without refunding unbilled rack rates. |
| **A17** | **Bulk Upload Validation & Error Quarantine** | Batch CSV upload for attendance (`student_id, date, status`) and tests (`student_id, date, test_name, score, max_marks`). Valid records commit atomically; errors quarantine with row-level feedback. | Core requirement for non-technical centre staff updating batch data. |
| **A18** | **Parent UI & Hindi Localization** | UI defaults to Hindi (`hi-IN`) with a 1-tap English toggle. Hero card renders only: Balance Due, Due Date, and "Pay Now" / "भुगतान करें" button (5-second rule on low-end mobile). | Directly addresses client constraints regarding parent tech literacy, low-end mobile devices, and fast dues clarity. |
